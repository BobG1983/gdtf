# The Litmus Tests

Quick questions to validate any design decision against the [pillars](pillars/index.md). If a proposed feature fails one, stop and reconsider.

1. **Does this generate a situation, or author an outcome?** If it scripts a fixed result or removes player agency, it works against the situation generator ([Pillar 1](pillars/1-situation-generator.md)).
2. **Does this leave a permanent mark, or wash away?** Costless do-overs and full heals between fights make the loop forget — and the loop's weight is that it *remembers* ([Pillar 3](pillars/3-every-fight-leaves-a-mark.md)).
3. **Is this a decision, or a stat?** If there's no meaningful choice with real downside, it isn't a mechanic ([Pillar 4](pillars/4-permanent-stakes.md)).
4. **Can the player read it at a glance?** If the state isn't legible, it can't drive a decision ([Pillar 5](pillars/5-readability-over-fidelity.md)).
5. **Does this make the roster more of a story?** Does it accrue identity (wounds / XP / grudges) or flatten gangers into interchangeable stat blocks? ([Pillar 2](pillars/2-the-roster-is-the-story.md))
6. **Could a dominant strategy emerge from this?** If the structure permits a single optimal play, that's a balance bug, not a number to nudge ([Pillar 7](pillars/7-balanced-by-construction.md)).
